# Sensory Considerations in App Design

## Understanding Sensory Processing

Many individuals with autism experience sensory information differently than neurotypical people. This can include:

- **Hypersensitivity** (over-responsiveness): Sounds, lights, or textures that seem normal to others may be overwhelming
- **Hyposensitivity** (under-responsiveness): May not notice sensory input that others find obvious
- **Sensory seeking**: Actively seeking out certain sensory experiences

## Visual Design Considerations

### Color Choices
- **Avoid overly bright or saturated colors** - can be overwhelming
- **Use calm, muted palettes** - easier on the eyes
- **Ensure sufficient contrast** - for readability
- **Be consistent** - sudden color changes can be jarring

### Animation and Movement
- **Minimize unnecessary animations** - can be distracting or overwhelming
- **Avoid flashing or strobing** - can trigger seizures or distress
- **Use smooth, predictable transitions** - rather than abrupt changes
- **Allow users to disable animations** when possible

### Visual Clutter
- **Keep interfaces clean and simple** - reduce cognitive load
- **Use adequate whitespace** - helps focus attention
- **Limit on-screen elements** - show only what's needed
- **Organize information clearly** - predictable layouts

## Auditory Design Considerations

### Sound Effects
- **Make sounds optional** - not everyone can tolerate them
- **Use gentle, pleasant sounds** - avoid harsh or startling audio
- **Provide visual alternatives** - don't rely solely on audio feedback
- **Allow volume control** - individual preferences vary greatly

### Background Audio
- **Avoid background music** unless specifically requested
- **No auto-playing audio** - unexpected sounds can be distressing
- **Clear audio feedback** - when sounds are used, make them purposeful

## Touch and Interaction

### Tap Targets
- **Large touch targets** - easier for varying motor skills
- **Adequate spacing** - prevent accidental taps
- **Clear feedback** - visual confirmation of touches
- **Forgiving interfaces** - allow undo or correction

### Gestures
- **Simple gestures** - basic taps and swipes
- **Avoid complex multi-touch** - can be difficult for some users
- **Consistent gesture meanings** - swipe right always means the same thing
- **Alternative interaction methods** - don't require specific gestures

## Specific GIRAF Considerations

### Pictogram Design
- **Clear, simple images** - avoid visual complexity
- **Consistent style** - same illustration approach throughout
- **Neutral backgrounds** - don't compete with the pictogram
- **Appropriate size** - easily viewable without strain

### Schedule Display
- **Clear visual hierarchy** - current activity obvious
- **Calm color scheme** - reduce visual stress
- **Adequate spacing** - activities clearly separated
- **Progress indicators** - gentle visual feedback

### Transition Warnings
- **Visual cues** - before schedule changes
- **Optional audio** - gentle sound cues if enabled
- **Countdown options** - for users who benefit from time warnings
- **Predictable patterns** - same warning style each time

## Testing for Sensory Considerations

When evaluating GIRAF designs, consider:

1. **Extended use**: Is the interface comfortable over time?
2. **Different environments**: Works in bright/dim lighting?
3. **Distraction level**: Does it compete for attention inappropriately?
4. **Recovery**: If overwhelmed, can the user easily return to a calm state?

## User Feedback Patterns

Signs that sensory design may need improvement:
- Users covering eyes or looking away
- Requests to turn off sounds
- Difficulty focusing on the intended content
- Avoidance of certain features
- Caregiver reports of distress
